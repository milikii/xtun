## 2. W05 交付

### 2.1 四种任务分开，菜单与 CLI 同一请求对象（D06）

- `install_task_ids/label/available/availability_text/default_id/selection_order` 定义任务集合：`fresh`（全新安装）、`resume`（恢复一次失败安装）、`rebuild`（按当前状态重建）、`rotate`（轮换凭据）；别名 `new/recover/reinstall/rotate-credentials` 保留。
- 有草稿时非交互入口必须显式给 `--task`（或 `--resume-draft`/`--rebuild-current`/`--rotate-credentials`），否则报「检测到未完成的安装草稿」并停下，不再静默加载上次输入；无草稿但有 state 时非交互自动 `rebuild`，两者都没有才是 `fresh`。
- 菜单第 1 项改成「安装 / 恢复草稿 / 重建（先选任务）」：先列可用任务（含可用性原因），有草稿时多一项「丢弃草稿并重新安装（全新安装）」，选完再 `run_cli_command install --task …`。CLI 与菜单最终落到同一个请求对象，不继承上次菜单的全局值。

### 2.2 向导顺序与输入预算（D06）

- 顺序固定为：连接地址确认 → SNI/target/CDN 域名 → 证书 → 基础组合/高级项 → 只读预检与影响摘要 → 一次最终确认。
- `prompt_validated_value` 逐项就地校验：格式错误只重问当前项，不把一次手误变成整轮重来；连续三次仍非法才终止。
- 干净环境 + 已有证书路径的一路回车安装是 **8 次输入**（含最终确认），自动凭据（UUID/短 ID/路径/REALITY 密钥）不占问答，只在内存里生成一次；返回修改、重试、重建都不重新生成。
- 确认页回车 = 取消（EOF 同样取消）；`advanced` 打开高级项、`back` 回到地址/域名/证书。

### 2.3 D05 新装默认（H05）

- 新装默认关闭：IPv6、WARP、网络优化、第三方内核、nginx 主配置接管、回国流量拦截、ECH、xpadding；VLESS Encryption 保持开启。
- 旧 state / 草稿 / 显式参数里的选择原样保留，已装节点的功能不会因为改默认值被自动关掉。
- 新装不再探测、也不再询问 IPv6（`--server-ip6`、草稿与 state 里的显式选择照旧生效），需要双栈时走确认页的 `advanced` 入口。

### 2.4 草稿的完整性与显式恢复（D06）

- 草稿带 schema、任务类型、来源、更新时间，权限 `0600`；键集合 = state 的键 + 草稿元数据/存在性标记。
- 敏感值写间接引用（`@路径`），正文不落草稿；还原时先保住显式参数再套草稿值，所以「显式参数 > 草稿 > 默认」的顺序不会被草稿反压。
- 只有「已确认」或本次已经保存过的动作才落盘；成功后清理，失败保留；恢复沿用草稿的身份与选择，不重新生成 UUID/短 ID/路径/密钥。

### 2.5 依赖分期与端口归属（D05/D07）

- `install_dependency_readonly_report` 在确认前列「已就绪」与「依赖准备后复检」，不装包、不假装通过；确认后 `install_prepare_and_preflight` 只装缺的包，再做深预检（证书与私钥配对在写盘之前）。
- 依赖失败报告「已装好的软件包保留；托管配置、state 与服务均未改动」，不把 apt 失败说成安装失败或成功。
- `install_resource_ownership_report` 把「空闲 / 本脚本托管可复用 / 外来不会停止或接管」分开说，外来 UDP 443 不会被当成可占用资源；未接管 nginx 主配置时给出可执行的后续动作。

### 2.6 本轮修掉的具体缺陷（均由实机暴露，都有回归）

1. **443 预检不可执行**：`preflight_check_port_443` 原来只说「端口已被占用，请先释放端口或确认是否为当前脚本托管服务」。实机上 `uninstall` 摘掉 `haproxy.cfg` 后 haproxy 仍以旧的内存配置监听 443，用户拿不到任何线索。现在点名占用者，占用者是托管服务名时直接给 `systemctl stop …`。
2. **非法输入重填等于死循环**：`prompt_validated_value` 把刚被判错的值留在变量里，下一轮提示把它当默认值显示，回车就是原样再交一次同样的错，三次之后整轮安装被取消。现在重填回到**上一次的合法值**。
3. **证书路径不可用后无法改**：`prepare_existing_cert_inputs` 见到任一非空路径就直接返回，重填只重问证书模式，坏路径原样再提交。现在重填前清掉不可用的输入（PEM 只填一半同样清掉）。
4. **重建/轮换的 existing 证书来源丢失**：state 只记证书模式、不记路径，`--task rebuild --non-interactive` 会卡在「请提供 --cert-file」。现在 rebuild/rotate 在既无显式参数又无草稿路径时回到托管路径，托管文件不存在则交给只读检查/预检报真实原因。
5. **连接地址输入不校验**：地址填错会被写进摘要和确认页，直到安装中途的 `validate_install_inputs` 才炸。现在地址在输入位置就用 `ensure_server_ip_format` 校验。
6. **rotate 可能换了个寂寞**：路径候选池只有 10 个，轮换后有 1/10 的概率拿到原值。`random_path` 现在支持排除原值。

实机过程中确认的两条环境事实（后续工单可复用）：

- **版本解析要打 `api.github.com`，匿名额度 60/小时**。本轮为了定位问题连续跑了多次安装，额度用尽后版本解析拿到 403（另一次是 404），安装按设计整代回退。验证脚本现在会先查额度、低于 30 次调用预算就带着说明停下，避免把限流误判成代码缺陷。
- **`uninstall` 之后 haproxy 可能以旧的内存配置继续监听 443**（配置已被删、reload 失败）。安装预检会因此停在端口占用；本轮把这条失败路径改成了可执行的提示（见 §2.6 第 1 条），根因留作后续工单。

实机结束后测试 VPS 处于：xray/haproxy/nginx 全 active，`/root/.xtun-install-draft.env` 与 `/var/lib/xtun/pending-op.tsv` 都不存在，UDP 443 仍是原先那个外来 hysteria 进程，`/etc/ssl/xtun` 是还原后的既有证书。

## 5. 遗留与后续输入

- **未覆盖**：极简镜像上同时缺 `openssl`/`iproute2` 的分支（本轮只制造了缺 `qrencode`）、真实 ACL 下 `sudo -u` 场景、交互式安装中途 Ctrl-C 的表现（W04 已覆盖变更类中断，安装类中断没有单独注入）。
- **`uninstall` 留下的端口残留**：卸载摘掉 `/etc/haproxy/haproxy.cfg` 后保留 haproxy.service 运行，reload 失败，进程继续按内存里的旧配置监听 443；再次安装会被新预检明确指出并给出命令。根因（卸载后服务未停、未 reload 成功的处理）不是 W05 的改动范围，留作后续工单输入。
- **GitHub API 匿名限流**：版本解析打 `api.github.com`，匿名额度 60/小时；连续多次安装会拿到 403，安装回退，终端只看到 `curl: (22) … 403`，没有「限流、稍后重试或用 `--xray-version` 指定版本」的解释。这是 W08.2（脚本与 bundle 身份）的输入。
- **草稿会沿用失败的版本请求**：草稿按 W08 记下这次动作的 `XRAY_VERSION_REQUEST`，`--task resume` 会继续用那个版本；要换版本得显式给 `--xray-version`。行为符合「草稿 = 这次动作的完整选择」，但需要在文档里说明（README 已补）。

## 1. 决策范围

<a id="d01"></a>
### D01：保留架构，以完整任务作为交付单位

继续使用现有 Shell 模块、systemd、HAProxy/Xray/nginx 及静态回落站。保留节点 1–9 的身份，不恢复订阅/mihomo，不引入管理面板、常驻代理或通用工作流框架。改动优先收敛到已有入口、请求解析、生成器、状态和运行恢复模块。

核心继续跟踪**最新官方已发布版本，包含预发布**；只在明确的新装/升级动作中应用，不增加后台自动升级。`v26.9.9` 是当前可复现依据，不是永久默认，也不改为 stable 优先。

首批设备保持 Android v2rayNG、Windows v2rayN、Debian NAS Xray-core Docker。交付单位是“完成安装并取得能用的节点”“修改一项并知道影响”“失败后恢复”“按归属卸载”，不是函数数量或菜单数量。

既有生产节点的保留要求持续有效。实施、故障注入和公开入口复测使用独立环境；正式发布与生产迁移分别排期。本次运行变更只使用用户授权的新测试 VPS，SSH 密码/配置保持不变；本机生产不迁移。

## 2. 命令、输入与取消

<a id="d02"></a>
### D02：先识别意图，再进入任何持久动作

统一执行顺序：**解析命令和参数 → 校验输入 → 读取当前状态/形成意图 → 预览并确认（交互动作）→ 锁与执行 → 验证结果**。锁前的状态和环境在获得锁后重新检查，防止并发期间变化；纯解析不依赖 root 或安装状态。

| 请求 | 允许行为 | 持久行为契约 |
| --- | --- | --- |
| 顶层/子命令 `--help`，未知命令/参数、缺值 | 输出帮助或具体错误 | 不建锁/日志/草稿/备份，不安装 bundle、依赖或重启 |
| 打开菜单、查看摘要/已有链接、选择退出 | 读取本地状态；按需使用临时运行包 | 不把临时入口安装到系统，不更新 state，不轮转备份 |
| `status` | 读取服务、文件和必要本地状态 | 不修复、不安装、不触发升级 |
| `diagnose` / `check-sni` | 明确的有界探测、临时结果 | 不重写配置、不隐式修权限；普通输出日志不成为持久操作日志 |
| 已明确的安装/变更/修复/升级/卸载 | 展示动作意图后执行其必要修改 | 在结果中说明发生了什么；参数错误仍应止于执行前 |
| 显式导出文件、显式保存草稿 | 写入用户指定/约定的私有产物 | 单独视为写入动作，不借机应用服务配置 |

运行命令的成功、失败和恢复可以记操作日志；日志入口带动作类型，不能把所有 `warn` / `die` 都当作允许写系统的理由。帮助在能本地识别时不取远端；确需下载模块的公开单文件入口只用临时目录，退出清理。

交互修改只做一次具体的影响确认。非交互命令的完整显式参数表达执行意图，沿用该命令既有的确认要求；卸载等破坏性入口保留显式确认/`--yes` 语义。缺输入或 stdin 关闭不能代替确认。

<a id="d03"></a>
### D03：输入必须保留“未给、禁用、给值”的区别

请求层区分 absent、explicit-disabled/empty、provided value；不再用一个空字符串兼任这些含义。优先级为：**本次 CLI 显式输入 > 本次明确选择的草稿/当前安装 > 新装默认**。已有 state 只能用于已选择的重建/变更任务，不能偷偷填进全新安装。

相反开关在任意顺序均报冲突，不采用最后一个覆盖前一个。`--no-ipv6` 是无值开关，禁用后不得由探测或旧 state 重新启用；显式地址也不得被空探测覆盖。参数在整体解析后统一检查，未知项、缺值、无效值不能落到安装阶段。

公开参数统一支持 `--key value` 与 `--key=value`；W03 已有对应实现与报告，后续新增参数仍须通过派发级测试后才在帮助中承诺。敏感值继续走已有文件/环境变量入口，不因统一解析而退回命令行明文。

证书模式内部只保存 `self-signed`、`existing`、`acme-dns-cf` 三个规范值。菜单展示三种唯一模式，快捷编号可采用 1/2/3，但由独立 UI 映射转换为规范值；不直接复用旧数字规范化函数。**旧 CLI 数字 2/3 → existing、4 → acme-dns-cf 的兼容含义保留并提示改用名称**，避免重新解释旧脚本。已有模式显示名称，直接回车必须保持同一规范值。

域名、IPv4、IPv6、host:port、UUID、shortId、path 分别验证。验证失败显示字段、原因和示例，保留其余有效输入；不输出敏感值。本轮先修现有 REALITY target 语法，不夹带扩展 IPv6 target 支持。

<a id="d04"></a>
### D04：返回、取消、失败都必须可预测

| 输入/事件 | 菜单或向导 | 直接 CLI |
| --- | --- | --- |
| 回车 | 仅在提示明确存在默认值时接受；必填无默认则留在当前字段 | 缺必要输入时明确失败，不自动选择 yes |
| 菜单 `0` | 子菜单返回；主菜单退出 | 不作为通用参数含义 |
| `:back` | 回到上一可编辑字段，保留有效输入和已生成身份 | 仅交互采集阶段适用 |
| `:cancel` | 放弃当前动作，返回菜单；确认前不持久写入 | 返回 130，说明取消而非失败安装 |
| EOF | 主菜单直接退出；向导放弃当前动作并结束会话，不重新读空输入 | 未完成必要输入返回 1，不执行默认动作 |
| Ctrl-C | 确认前取消当前动作；执行中进入清理/恢复，显示结果后返回可用入口 | 清理/恢复后返回 130 |
| TERM | 执行必要清理/恢复后结束会话 | 返回 143 |
| 可恢复输入/操作错误 | 就地重填或显示失败后返回菜单，不递归调用菜单 | 参数/运行错误返回非零 |

保留 `check-sni` 的退出码：参数错误 1，存在硬性检查失败 2，仅 WARN 为 0。其它运行错误通常为 1；恢复失败在结果中明确标识，不与“已恢复旧状态”共用成功提示。

内部统一记录 `success / noop / cancelled / failed / recovery_failed` 等动作结果，菜单消费结果，不能靠 `|| true` 把失败变成成功。每次动作初始化请求、版本选择、临时路径和恢复上下文；菜单缓存仅用于显示，不能当作下次修改的输入。

执行阶段收到中断也要遵循恢复边界。包管理或外部注册无法保证瞬间撤销时，显示“正在结束当前步骤”及已保留资源，不能承诺未发生任何变化。掉电后的未完成操作由下次明确维护动作识别和处理；仅查看状态不自动恢复写入。

## 3. 安装与日常交互

<a id="d05"></a>
### D05：新装默认值服务于可理解的基础组合

以下是完整目标默认值；已有安装保留显式选择，迁移不得借默认变化轮换凭据或关闭功能。W05 已交付 IPv6、WARP、网络优化/内核、nginx 主配置接管等新装默认；**批次 B / W09.1 已补齐 H3 新装默认关闭及显式意图**。真实路径仍按 W15 验收。

| 项目 | 新装决策 | 用户需要理解的影响 |
| --- | --- | --- |
| 核心版本 | latest-published，含预发布；单次动作锁定 | 预览显示精确 tag，回退可显式选 tag |
| 主节点 | 保留基础 1–5 | 各节点能否实际使用仍取决于对应域名、证书和客户端 |
| IPv4/连接地址 | 展示探测候选，由用户确认/改填 | 探测失败时要求输入，不写无效值 |
| IPv6 | 默认关闭；高级项明确启用并验证 | 回车不会自动多出节点 6/7 |
| REALITY SNI / target、CDN domain | 分别收集并验证 | 受控连接地址、第三方 SNI 和橙云域名不混用 |
| UUID / 密钥 / shortId / path | 自动生成一次；高级项允许设置 | 返回、重试、重建不隐式轮换 |
| 节点前缀 | 自动建议，可在高级项改名 | 不占基础安装的必要问答 |
| XHTTP VLESS Encryption | 延续默认开启 | 双端必须配对；不能为 GUI 测试通过而静默关闭 |
| ECH / xpadding | 默认关闭，显式启用并按层导出 | 不把可选能力当作已通过的基础路径 |
| H3 | 默认关闭；显式启用且能力检查通过 | 需要对应公网信任证书、nginx 支持及 UDP/443 条件 |
| WARP | 默认关闭 | 开启涉及外部注册、路由和凭据 |
| 网络优化 | 默认关闭 | 开启前展示具体 sysctl/qdisc/文件改动 |
| Joey 等第三方内核 | 默认不安装 | 仅独立高级动作选择，说明重启需要与外部依赖 |
| nginx 主配置接管 | 默认关闭 | 需要接管时展示原件、影响与恢复依据，明确选择 |
| Block CN 等额外路由 | 默认关闭，已有选择保留 | 展示命中范围，不误称为性能选项 |
| 证书 | 首次显式选择已有/ACME/测试自签，显示路径适用范围 | 自签不等于公网可信；existing 不等于 H3 可用 |

IPv6、H3 和 ECH 的“关闭”是新装默认，不能据此删除旧配置的选择。旧状态无法证明意图时显示待确认项，不从功能探测成功反推用户已经启用。

<a id="d06"></a>
### D06：安装向导先处理必要条件，再处理自动值

四种任务必须分开：**全新安装、恢复一次失败安装、按当前状态重建、明确轮换凭据**。有现存安装时先呈现任务选择，不把“安装/重装”解释成自动生成新身份。CLI 与菜单最终形成同一种请求对象。

基础向导顺序：

1. 识别安装/草稿状态并选择任务，读取环境与资源归属。
2. 确认连接地址；输入 REALITY SNI、实际 target、CDN domain，逐项校验。
3. 选择证书来源，收集该模式必需的路径或间接凭据，说明能支持的路径。
4. 显示基础组合与高级设置入口。自动凭据不逐个发问；需要时在内存/私有 staging 生成一次。
5. 展示预检结果和待依赖工具才能完成的检查，给出一页影响摘要。
6. 一次最终确认后准备依赖、完成深预检、生成候选、验证并应用；失败停在明确阶段。
7. 显示结果、服务状态、节点摘要、获取路径和下一步，长资料写入私有文件。

草稿必须包含 schema、来源/基线、任务类型、完整选择及更新时间；明确恢复或丢弃，不能静默加载上次输入。保存文件为 0600，敏感输入使用既有间接引用并按需重填，日志/报告不打印内容。确认前只有明确的“保存草稿”动作才写文件；执行后的失败可保留已确认草稿。成功后清理/归档该草稿，不能污染下一次新装。

接受上一字段默认值、返回修改域名和重试预检均不重新生成 UUID、路径、密钥。显示来源为“本次输入/已保存选择/自动生成”时只展示必要非敏感摘要。

交互目标作为待测门槛：干净环境、已有证书基础路径在地址可探测时，**不超过 8 次必要输入（含最终确认）**；ACME 等分支另计必要字段并报告原因。安装概要适配 80×24 终端，自动值不占连续问答。该数字是本轮设计目标，不是当前测量结果。

<a id="d07"></a>
### D07：解决最小依赖与“确认前不改系统”的冲突

确认前只做可用工具支持的只读检查；缺少 openssl/iproute2 等时明确列为“依赖准备后复检”，不假装通过，也不静默 apt 安装。确认后先准备已展示的最小依赖，再完成关键检查，**在托管服务配置应用前**阻断失败。

最小检查包括系统/架构、systemd、磁盘/目录权限、工具、时间、地址与 DNS、TCP/UDP 端口和进程归属、证书文件、现有 nginx/HAProxy/Xray/WARP/ACME 资源。依赖安装本身的系统包保留不等于托管服务回滚失败；结果分别列出“已安装依赖”“托管配置是否变动”“服务是否恢复”。不承诺包管理、内核或第三方注册具备文件事务级回滚。

网络探测都有限时。现有 `check-sni --timeout` 保留每个探针预算，默认 10 秒，只接受正整数并规范化前导零；DNS、TLS、证书、HTTP 和子重试都纳入预算。显示当前阶段与该轮总预算上界，同一数据采集一次，显示与判定复用结果。

输入格式错误不能忽略。保留现有 SNI `r/i/q` 的重填、明确忽略本次网络检查、退出意图；选择忽略的结果始终标为未通过/未验证，不能改写成 PASS，也不持久化为今后的默认跳过。

<a id="d08"></a>
### D08：菜单按用户任务组织，变更先说明影响

未安装时只展示安装、环境/SNI 检查、帮助和退出。已安装入口分六组：

| 任务组 | 包含内容 |
| --- | --- |
| 获取节点 | 摘要、复制链接、单节点 QR/PNG、NAS 配置 |
| 查看状态与诊断 | 快速状态、深诊断、SNI 检查、上次动作结果 |
| 修改节点 | UUID、路径、SNI/domain、证书来源、节点相关设置 |
| 升级与维护 | 核心升级/显式重装、脚本更新、重启、修权限、重建配置 |
| 网络与可选功能 | WARP/规则、IPv6/H3/ECH、网络优化/内核 |
| 恢复与卸载 | 操作/备份详情、按归属恢复、卸载 |

菜单编号可以在本轮调整，发布说明列旧入口与新任务组；现有 CLI 名称和节点编号保持稳定。菜单不自动跑深诊断/外网探测；常用节点获取最多两级。

影响预览至少包括：旧值→新值的非敏感摘要、受影响链接、会 reload/restart 的服务、可能中断的连接、要写的托管范围和恢复点。不要以“配置已更新”代替这些信息。

| 修改 | 必须重新导入的节点（存在且启用时） | 连接影响 |
| --- | --- | --- |
| REALITY UUID | 1、6 | 若重启共享 Xray，所有经过它的连接都可能中断 |
| XHTTP UUID / Encryption / path | 2、3、4、5、7、8、9 | 同上 |
| REALITY SNI / 公钥对应密钥 / shortId | 1、2、4、5、6、7 | 按生成差异应用；重启影响不局限于这些链接 |
| CDN domain | 3、4、5、7、8、9 | 按证书、nginx、HAProxy/Xray 变化说明 |
| WARP 规则 | 通常无链接字段变化 | Xray 更新或出站切换仍可影响现有连接 |
| 续证，同一主机名与参数 | 通常不需重新导入 | 只执行必要 nginx 动作并验证 |
| 仅导出/修改备注 | 按用户需要取得新产物 | 不应用服务配置 |

相同输入先比较规范化请求及实际候选差异；无变更就返回 noop，不备份、不重启。显式 restart/repair 表达了修复意图，仍执行其规定动作并报告实际结果。

## 4. 状态、版本与恢复

<a id="d09"></a>
### D09：展示事实、检查结论和建议，分开表达

快速状态只报告已知事实：安装身份、服务 active 状态、TCP/UDP 监听和归属、证书到期信息、最近动作结果。深诊断报告 `通过 / 失败 / 未验证 / 不适用`，保留原始原因与可执行的下一步；不能用“功能开关=yes”表示传输已成功。

SNI target 解析规则：显式 `--target` 优先；无显式域名时使用保存的 SNI 与真实 `REALITY_TARGET`，缺 target 才回退 SNI:443；显式域名但未指定 target 时使用该域名的默认目标，不带入旧节点的 target。CLI 的 server-ip 不被 state 覆盖。TLS/HTTP/证书探测采用同一目标和端口，逻辑 SNI/Host 保持正确。

协议可用性、证书事实、站点策略风险与延迟建议分别判定。CA 品牌不是 CDN 身份证明，慢一次不是协议不兼容，相对重定向按实际 URL 解析。PQ 观察继续后置，不把签名准备度变成普通安装门槛。

H3/ECH 等能力显示至少区分：用户已启用、组件/参数支持、证书与端口条件、已验证的网络和客户端组合。菜单可以提示能力条件，不能在安装过程中宣称未来客户端已经验证。

<a id="d10"></a>
### D10：版本上下文属于一次动作，身份属于安装结果

复用现有 latest-published 解析/下载，不退回 `/releases/latest`。一次操作锁定 tag/commit/资产/摘要，下一次菜单动作清空上下文重新选择；网络失败、资产缺失或校验失败不得自动换成旧核心或旧 bundle。

安装清单记录脚本版本与准确 ref/commit、核心 tag/commit/二进制身份、下载和 geo 资源摘要、参数修订、状态版本。校验摘要表示完整性，不描述为独立发行签名。bootstrap 脚本与 bundle 使用同一解析后的 ref；候选必须含完整运行文件集合及共享版本模块。

相同可信 tag/安装身份且无需修复时，升级显示“已是当前目标”并返回 noop。只有相同版本字符串、缺安装清单时显示“同版本，产物身份未核验”，不得既宣称完全相同又悄悄重装。**计划新增 `upgrade --reinstall`** 表达真正重新安装的意图；其余参数与版本策略一致，仍需要候选检查和恢复保障。

候选命令、密码学输出和配置验证全部显式检查返回值及结构，不依赖 `set -e` 的调用上下文。临时文件属于唯一操作目录；完整通过后才替换二进制/资源/bundle。基础小 JSON 检查之外，加入实际生成的服务端与五类参照客户端配置验证。

<a id="d11"></a>
### D11：有归属证据才接管、恢复或删除资源

资源清单至少记录路径/服务/包或外部资源、操作前是否存在、原件位置与摘要、是否由 xtun 创建、接管意图、当前操作 ID。文件存在或名字相似不代表 xtun 所有。首次 nginx 主配置接管原件独立保存，生命周期持续到确认恢复/解除托管；不能被“最近五份备份”轮转掉。

每次动作使用唯一 ID，首次备份不可覆盖。对同一路径的后续备份复用首次快照；原本不存在也要显式记录。备份轮转发生在成功动作完成及恢复点保留条件满足后；帮助、取消、noop 不产生备份或淘汰旧备份，未恢复失败的证据不自动清走。

卸载先展示归属清单。只停止/删除确定托管的单位与文件；外来 hysteria/nginx/WARP/ACME 安装和共享包默认保留。旧安装缺归属元数据时采用保守模式：恢复有可信原件的项，保留无法证明的项并报告，不写默认 nginx 配置冒充恢复。清除包或外部注册须属于已明确选择的清理范围。

恢复时，只有“原本不存在且本次确实创建的托管路径”才能删除。缺备份文件不能自动解释为“以前不存在”。

<a id="d12"></a>
### D12：一次托管变更以同一代文件和可用服务为完成条件

沿用并收敛现有 workflow/runtime 层：准备操作清单和首次快照 → staging 生成 → 静态/配置验证 → 应用 → 有界健康检查 → 确认完成。配置、核心/geo、state、必要链接文档和启用的 PNG 集合使用同一代身份。跨多个文件的改动不宣称由一次 `mv` 全局原子完成；用操作日志、受限切换窗口和可验证恢复保证一致性。

成功要求：候选文件通过检查，服务实际达到所需状态，state 与导出对应实际运行代，输出路径有效。运行阶段任一必需步骤失败则恢复前一代文件和服务，并再次检查；恢复失败明确显示仍不可用的组件与最后可信恢复点，不输出成功。

新装以 PNG 为默认交付物，生成依赖与失败在提交前处理。凭据变更不得成功切换后继续向用户提供上一代二维码；staging 输出失败则停止提交。独立的显式导出失败只影响该目标文件，不回滚或重启服务。非关键日志追加失败单独警告，不能因此反复变更服务。

恢复承诺覆盖本工具托管的文件和服务；包安装、第三方内核、WARP 注册等单独记录可撤销与保留动作，不能用“完整回滚”掩盖外部副作用。执行中断/掉电需要保留可识别的未完成操作清单。该清单属于 D20 的必需恢复证据，不适用“非关键日志失败仅警告”的策略；H27–H29 已由 A 批补修并保留回归，强制断电证据仍待补齐。

<a id="d14"></a>
### D14：参数迁移以旧身份不变和真实路径正确为前提

继续执行 [参数契约](PARAMETERS.md)，先修 H3 ALPN、IPv6 split 和错误的无效选项，再做有版本门槛的 users/xmux/ECH 迁移。

VLESS 兼容读取旧 clients 与新 users；处理两者同时存在/空数组的优先关系，写出一种规范结构，不丢 UUID、flow、Encryption 或定制。旧 xmux 若属用户显式配置则保留；能证明为旧生成默认的值才按迁移策略调整，不能简单匹配数值就认定用户无意选择。原生 REALITY 使用目标版本规范字段，URI `pbk` 与 GUI 别名按真实客户端测试兼容。

清理无效 `XHTTP_ECH_FORCE_QUERY` 的设置/展示入口，旧 state 可读取并提示无效，不伪造核心支持。ECH 普通/启用变体分别命名，优先真实 CDN 域名的 HTTPS/ECH 信息，AliDNS 为可替换首轮候选，共享名是显式备选。已配置 ECH 的连接失败不能自动删字段或回退普通 TLS；用户可明确选择 plain。

节点 7 上行仍为 CDN，只有 REALITY 下行变为 IPv6；节点 9 下行的 H3 ALPN 位于下载流的 TLS 设置。xpadding 按使用它的各层统一表达。H3 开启需要证书、组件与端口条件，实际支持声明还需真实 UDP 路径证明。不能添加已在该核心移除的 `allowInsecure=true` 来绕过证书错误。

后续 latest 变更重新核对官方 docs/source 与准确核心。参数修订、状态迁移和核心升级共同形成可恢复候选，不按“最新模板”覆盖旧安装。

<a id="d15"></a>
### D15：证书类型、路径能力与自动续期分开管理

证书模式只描述来源。证书能力单独验证公私钥匹配、SAN、有效期、完整链和对应信任用途：公网信任、Cloudflare Origin CA、测试自签、未知。Origin CA 可适用于正确配置的 CDN 回源，不能推出终端直连 H3 受信；自签选择必须明确其测试/特定回源用途。

人工换证、renew 和 ACME 自动回调共享锁、staging、验证、成对提升与恢复流程。先确认候选证书适用于当前域名，再对 nginx 做最小必要应用并检查实际提供的证书。只更新证书且链接字段不变时不重启 Xray/HAProxy、不轮换 UUID，也不要求用户重导入。

自动回调失败保留旧证书/服务和可定位结果；不因 acme.sh 外层返回成功就宣布部署成功。测试覆盖回调已移动 staging 文件、主流程再次读取、并发人工维护、reload 失败与证书过期前告警。共享 ACME 安装及其它域名证书按 D11 归属保留。

<a id="d20"></a>
### D20：恢复证据必须可靠，恢复目标是操作前状态

H27–H29 表明，原件、manifest、未完成清单和服务快照属于必须成功的执行前提，与可选过程日志分开处理。W02-R/W04-R 按以下规则补齐：

1. 同一动作、同一路径的首次记录不可改变；原本不存在与原本存在同样有效。后续创建/修改不重写这条记录，恢复只删除可证明为本次创建的托管路径。
2. 清单初始化/写入/持久化/回读或原件校验失败，必须在相应托管目标变更前阻断。证据缺失不等于原本不存在，也不能用候选文件补作原件。
3. 修改前持久化完整的受影响路径和服务清单，涵盖该动作涉及的核心、geo、bundle、配置、state、客户端产物和 unit/drop-in。追加路径须先保存可靠恢复依据，不能只更新内存。
4. 恢复服务的实际操作前状态：active、inactive、未安装/不存在分别处理；本次修改的 enable 状态一并恢复。不能只重启原来 active 的项，忽略本次意外启动的服务。
5. 必需 daemon-reload、停止/启动/reload、文件或产物恢复及核验失败都报 `recovery_failed`。原动作失败但旧状态已恢复仍是原动作失败，不能返回原动作成功。
6. INT/TERM 的 trap、SIGKILL 后重入和强制断电恢复分别验证。未完成标记的持久性需有文件系统及隔离演练证据，不因单文件 rename 就承诺跨文件原子或掉电安全。

共享服务的配置与 unit 归属分别决定恢复/清理。没有可信原件时保留必要资源并报告未完成；不能删除共享 HAProxy 配置、忽略 reload 失败，再让保留进程持续占端口却报告完整卸载。历史报告仍保留，新结论由补修证据更新。

### D27：菜单动作隔离，确认以当次预览为准

## 8. C/D/E 实施决策（2026-09-15）

<a id="d33"></a>
### D33：安装回执证明本机产物，来源不冒充签名

bundle 回执包含全部 `xtun.sh/lib/static` 文件摘要、入口摘要、来源、ref/commit 与归档摘要。默认公开引导先解析固定 commit，再校验同一 commit 的 raw 入口与归档；元数据错误不回退浮动 main，写动作失败不调用旧 bundle。自定义远程包必须给 SHA256，本地文件包记录 local-archive，不伪造 Git commit。

核心回执核对官方 tag/commit/架构与归档摘要，同时记录二进制、两份 geo、二进制属主/模式/capability。相同可信身份为 noop；缺少或漂移的回执要求显式重装。回执不是上游签名，也不能证明维护者账户未被入侵。额外签名仍归 W17。

<a id="d34"></a>
### D34：核心、bundle 和参数各按自己的范围提交

`upgrade` 只操作核心/geo/核心回执和 Xray 服务，`update-script` 只操作 bundle 与管理入口；都不暗中改 state、UUID 或客户端参数。旧配置的 users/产物迁移由用户显式执行 `apply-config` 等托管配置动作。分别验证各自恢复范围，不宣称三次动作是一个不可分割的事务。

参数修订为 2，state schema 保持 2。安装回执内的 schema/参数版本描述创建回执的代码能力，生效参数以 state 的 `PARAMETER_REVISION` 和生成产物清单为准。旧 state 没有该字段时显示/记录未知，不用新 bundle 版本冒充已经完成参数迁移。

<a id="d35"></a>
### D35：保留旧客户端调优，拒绝丢失配对身份

旧客户端 URI 中的 xmux/scMinPostsIntervalMs 按节点和上/下行提取保存；显式 state 优先，不能因数值碰巧等于旧默认就删除。旧文档缺失且参数来源无法核实时保留兼容值并警告；新装省略这组字段，使用已核对的核心默认。

目标核心中非 null 的 clients 优先于 users，包括空 clients。有效列表为空则停止，不能用 state 重新创建被删除用户。写出当前支持的规范字段，保留有效首用户的扩展字段/flow；沿用既有单用户产品范围。缺客户端 Encryption 配对时停止，不为了生成文件轮换服务端密钥。新 ECH 入口默认查询真实 CDN 域名的 HTTPS 记录，旧共享名/IP DoH 值照旧保留。

<a id="d36"></a>
### D36：证书部署成功必须有实际供证证据

共享验证检查私钥匹配、DNS SAN、有效期、服务器用途和信任链。Origin CA 用官方 RSA/ECC 根验证签名，不靠 issuer 名称；测试自签验证自身签名。ACME 要求公共信任，Origin CA/自签不能放行直连 H3。

每个独立证书进程先以 lookup 方式读取 Xray UID/GID。证书、私钥及相关元数据进入同代快照；两文件分别提升，期间任何失败都恢复，并核对 nginx 实际提供的旧证书。该实现不把两次 rename 称为文件系统原子配对替换。成功只 reload nginx；同域名不重写 Xray 配置、URI/PNG 或要求重导入。

<a id="d37"></a>
### D37：ACME 外层退出码不足以确认回调成功

已核对 acme.sh 3.1.1 的 `_installcert`：reloadcmd 失败可能只写 `Reload error`，外层仍成功；`RENEW_SKIP=2` 表示未到续期时间。人工调用持有共享锁，回调验证继承锁、当前 operation、nonce 和 staged 文件摘要，只回报确认，不移动/部署。外层收到本次确认后再成对复制、校验与部署。

定时回调独立取得同一锁，核对当前域名和证书来源后执行相同恢复流程。源文件丢失/变化、回调未确认、reload 后供证未变化，都返回失败；失败恢复不能完成时保留 pending。公共 CA 签发、账户注册和 DNS API 外部效果不承诺回滚。证书事件记录与实际供证回执供诊断，不将 acme.sh 的返回码等同于节点已换证。

<a id="d38"></a>
### D38：导出与二维码重建只发布可核对的产物

当前代的节点清单同时绑定 config/state/文档摘要与每张 PNG 的摘要。导出持锁，拒绝 pending、托管目标、符号链接和不支持组合；新文件 0600，新建父目录 0700。默认发布用同目录原子 hard link 防止检查后出现的文件被覆盖；显式覆盖才替换目标，校验/编码失败保留旧文件。

`rebuild-qr` 逐字比较规范对象 URI 与已交付文档，才重建整套目录；缺整个目录可恢复，旧文档定义不一致则要求先显式迁移，不能只把 PNG 换成新语义。新安装缺 qrencode 时在发布节点文档前失败，不能提交半套产物。

NAS JSON 默认监听 `127.0.0.1:10808`。Debian NAS 首轮说明采用 Linux host 网络，以保持导出 JSON 不需手改；以文件属主 UID/GID 运行官方固定 digest 镜像，继续保持 0600 和只读挂载。另需 bridge 时必须显式准备容器内监听地址并单独验收，不把 host 网络结果当成 bridge 结果。

<a id="d39"></a>
### D39：原生参照、历史迁移、容器与真人各证明自己的范围

原生套件在独立 network namespace 中运行当前核心、nginx 和内容服务器，保留 private 路由防护，正向核对双向 64 MiB 与哈希，split 使用双腿字节计数和逐腿阻断。私有 CA/nginx 适配器和原生 ECH 监听只证明协议组合，不证明 Cloudflare、GUI 或公网 H3。

## 9. 接管还原补充决策（2026-09-19）

<a id="d40"></a>
### D40：接管宿主已有的 xray.service 与核心必须登记并可还原

安装到一台已经有自己 Xray 服务的机器时，`/etc/systemd/system/xray.service` 与 `/usr/local/bin/xray` 属于别人，不是 xtun 的产物。首次接管必须登记原件与当时的启用/运行状态；卸载时按登记**还原**这些路径并报告结果，只有确认是 xtun 自己创建的（`existed=0`）才删除，且不因还原成功改变原动作的失败码。

接管范围包括宿主服务依赖的运行目录与资源/配置目录（`/var/log/xray`、`/var/lib/xray`、`/usr/local/share/xray`、`/usr/local/etc/xray`）：接管前已存在就应登记并在卸载时还原，不能让还原后的服务因为目录消失而起不来。目录接管已补齐——`record_takeover_original` 对目录用 `mktemp -d`，`restore_takeover_original` 增加目录分支（先拷临时目录校验，再移除目标改名）。

**安装前必须告知**：只读检查的「端口与资源归属」要列出安装前已存在、会被接管的托管路径（unit 附 enabled/active 状态），安装摘要同时给出一行接管说明；不能只报端口占用，也不能静默覆盖。依据 H31–H33 与 D11/D20.1/D20.4。

<a id="d41"></a>
### D41：包归属不等于服务在用，共享服务按安装前的实际运行状态判定

卸载时要不要把 `haproxy`/`nginx` 当共享服务保留，看的是**服务在安装前有没有真的在用**，而不是包是谁装的。安装前已经 active 或 enabled 的，按共享服务保留运行、还原并 reload 原配置；只是装了包、从未启用的，视为 xtun 引入，卸载时停用并清理 xtun 的配置，避免 443/80 被一直占着、导致还原后的宿主服务起不来、卸载恒返回非零。

判定依据是首次接管时记录的服务启用/运行状态（`/var/lib/xtun/originals/service-state/<unit>.state`）；没有记录的老安装保守地按共享在用处理。包本身仍按原归属决定是否可 `--purge`，不因这条决策改变。依据 H34 与 D11/D20.4/D25。

<a id="d42"></a>
### D42：后量子就绪度只观察不拦截

`check-sni`（安装与改 SNI 预检）增加「后量子就绪度」观察项：用本机 openssl 的默认分组做一次带 SNI 的握手，记录协商到的密钥组与证书链总长度。只有协商到后量子混合组（如 `X25519MLKEM768`）**且**证书链严格大于 3500 字节才 PASS；其它已测得情况（未协商到混合组、链长不足、字段缺失、命令不可用）一律 WARN。

WARN 只增加告警计数，不产生 FAIL、不改变退出码，也不阻断安装；`--skip-sni-check` 仍跳过整组预检。该阈值是给将来的后量子/签名配置准备度用的观察指标，不是现有 Reality 节点的可用性门槛，也不代表已启用后量子签名或 ML-DSA。探测不新增 CLI 开关、状态键或后台巡检，并与既有 TLS/证书/HTTP 探针连同一个 target；本机 openssl 不支持 ML-KEM 时只如实记录协商结果，不据此断言目标站不支持。依据 W17 与[归档计划 §3.2](archive/PLAN-2026-09-12.md)。

## 2. W06 交付

### 2.1 检查的是真实 target，不是 SNI:443（H08/D09）

- `xtun check-sni` 无参数时用 state 里保存的 `REALITY_TARGET`，不再把 SNI 重造成 `SNI:443`；实测保存 `upstream.example:8443` / 实机 `3.33.186.135:443` 时探测的就是保存的那个主机端口。
- 显式给域名时用**该域名自己的默认目标**（`域名:443`），不带入旧节点的 target；显式 `--target` 优先于两者。
- CLI 传 `--server-ip` 时不被 state 里的旧地址覆盖；TLS/HTTP/证书四个探针共用同一个 target 与端口，逻辑 SNI/Host 保持为域名。
- 目标值走 W03 的 `validate_hostport_value` 校验；读数只在需要默认值时才碰 state，**只读、不写**（`check-sni` 不改 state，实机按文件对比验证）。
- CLI 帮助（`lib/base/input.sh`）与 README 的 `check-sni` 行同步成「默认用已保存的 `REALITY_TARGET`，显式域名用该域名:443，`--timeout` 必须是正整数」，不再写「默认 SNI:443」这种与实际行为相反的说明。

### 2.2 等待有上界，探针不重复（D07）

- 新增 `sni_normalize_timeout`：`0`、`00`、`000`、`-1`、`abc`、`1.5`、空值全部拒绝并点名 `--timeout`；`010` 规范化成 `10`，上界按规范化后的数字算。
- 新增 `sni_probe_dns host timeout`，用 `timeout` 包住 `getent`：退出码 `0` 有记录 / `2` 无记录 / `124` 超预算 / `3` 找不到 `getent`，四种结果分开报。
- `run_sni_checks` 先公布「等待上界: 4 个探针 × Ns = 4N s，每个探针只跑一次」，再逐阶段打印 `[1/4]…[4/4]` 与每阶段耗时；结论行带「本轮等待上界/实际」，黑洞目标实测整轮 10s（上界 12s）。
- `sni_now_epoch` 在 `date` 不可用时返回 0，避免计时退化成算术报错。

### 2.3 HTTP 跳转与「CA 品牌 ≠ CDN」（D09/H18）

- 新增 `sni_redirect_is_relative` / `sni_redirect_host`：`/path`、`path`、大小写、带端口/userinfo、协议相对 `//host/path` 都按实际 URL 解析；相对跳转只 WARN「相对跳转，仍在本主机」，跨主机给出真实主机名，3xx 无 `Location` 也单独 WARN。
- 证书签发者不再充当 CDN 证明：证书判定里的 CDN 项改成「未验证：签发者「…」只说明证书链来源，不能证明站点在 CDN 后」，聚合层新增独立的 `未验证` 计数，结论行写「N 未验证」。4 个真实站点（含 CA 相同与不同）只给同一句「未验证」。

### 2.4 跳过 / 忽略只对本次动作有效（D09）

- 新增全局 `SNI_PREFLIGHT_SKIPPED` / `SNI_PREFLIGHT_IGNORED`，**不是 state 字段**：跨进程、跨动作都不会留下「已验证」的假象。
- 跳过只在本次安装里把结论标成「未验证（不因跳过变成通过）」并保留失败事实；交互选择忽略时说明结论没有改变；两者都在安装预检阶段和部署完成后各报一次，并给出公开复检入口 `xtun check-sni`。

### 2.5 一次采集，展示与判定复用（H21/D09）

- 新增采集函数：`port_listening_snapshot`（`<state>|<text>`，文案形如 `TCP 运行中 (*:443 · haproxy)`）、`quic_port_state` / `quic_port_text_for_state`（`na` / `unknown` / `absent` / `ok` / `unconfirmed` / `foreign`）、`local_tls_probe_state`（带 `XTUN_LOCAL_TLS_PROBE_TIMEOUT`，默认 5s，`timeout` 包裹）、`local_tls_probe_text_for_state`、`certificate_usage_text`、`ipv6_listen_text`。
- `xtun diagnose` 重写为一次采集：service、配置校验、TLS、端口快照、QUIC、网络、WARP 出口各只算一次，展示与判定读同一份结果；实测整轮 4–5s。
- 端口行写明 TCP 与归属（`监听 443: TCP 运行中 (*:443 · haproxy)`）；`[::]:443` 行同样写明 TCP；新增 `QUIC 443`、`证书用途`、`外部可达: 未验证`、`客户端兼容: 未验证` 行。
- 没有 `ss` 时报「无法确认（缺少 ss）」，不报成「未监听」这种确定结论；`tls_state=na` 仍是故障，自签下的 `untrusted`（握手成功但证书不受系统信任）不算故障，`acme-dns-cf` 下不受信任才报。
- 面板（`lib/ui/dashboard.sh`）端口行加 `(TCP)` 标注，体检面板新增 `QUIC :443 (UDP)` 行。诊断是只读动作：不写 state、不执行 repair/apply（实机按计数与文件对比验证）。

### 2.6 安装报告措辞

- H3 行从「条件具备」改成「已配置启用；UDP 443 监听: …」，把「开关打开」和「UDP 443 真的有监听」分开说。

### 2.7 本轮修掉的具体缺陷（实机暴露，都有回归）

1. **显式 CLI 值被 state 静默覆盖**：`install --task rebuild/rotate --non-interactive` 时 `load_existing_state` 会用 state 旧值盖掉本次显式参数（实测显式 `--reality-target 3.33.186.135:443 --cert-mode existing` 全被覆盖）。现在 `lib/install.sh` 把「快照显式值 → 加载来源 → 回填」提炼成 `install_snapshot_provided_values` / `install_restore_provided_values` / `install_load_existing_state_preserving_provided`，rebuild|rotate 分支按「显式 > state > 默认」加载。回归 `run_install_rebuild_explicit_input_case` 在旧代码下会失败。
2. **IPv6 双栈行是裸「运行中」**：诊断里 `监听 [::]:443: 运行中` 看不出是 TCP 还是 UDP，正是 H21 要修的那类标注。新增 `ipv6_listen_text`，分「TCP 运行中 / TCP 未监听（仅 IPv4）/ TCP 未监听 / 无法确认（缺少 ss）」；实机断言「IPv6 双栈行也写明 TCP，不是裸「运行中」」。

## 4. 测试 VPS 实测

环境（与 W05 同一台专用测试 VPS）：Debian 12 x86_64，全局 IPv6 `2a01:7e01::2000:faff:fe0f:7250`；无 Docker；UDP 443 空闲（hysteria 已按用户要求彻底删除，unit/bin/目录/用户全无）；TCP 443 由托管的 haproxy 占用；nginx 默认站点是外来站点（不动）；nginx 1.22 没有 `http_v3` 模块。

实机过程中确认的两条环境事实（后续工单可复用）：

- **nginx 1.22（Debian 12）没有 `http_v3` 模块**，所以 H3 的真实 UDP 监听在本机无法成立；本轮把它如实渲染成「不检查（H3 未启用）＋原因」，真实 UDP 监听验收留给 W11/W12。
- **诊断整轮 4–5s**，本机探测（TLS 5s 上界、DNS/端口快照）全都有界；慢的是外部网络，不是本机采集。

实机结束后测试 VPS 处于：xray/haproxy/nginx 全 active，`REALITY_TARGET=www.stanford.edu:443`、`CERT_MODE=existing`、state 无跳过/忽略残留，UDP 443 空闲。

## 5. 遗留与后续输入

- **H3 真实 UDP 监听未验收**：Debian 12 的 nginx 没有 `http_v3` 模块，本轮只验证了「不适用要说清原因」；真实 H3 监听与 Alt-Svc 验收留 W11/W12。
- **外部可达与客户端兼容仍是「未验证」**：本机诊断不代替外部探测和真实客户端，需要 W15 的三端导入实测。
- **`uninstall` 留下的端口残留**（W05 遗留）：卸载后 haproxy 可能以旧内存配置继续占 443，本轮没动根因。
- **IPv6 双栈行的判定口径**：`TCP 未监听（仅 IPv4）` 依赖 `ss` 输出里的 `[::]`；若日后容器里 `ss` 表现不同，需要按实际样本再核一次。

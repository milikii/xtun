## 1. 结论

上一轮确实完成了核心追新、CI 修复和一批实机问题修复。当前需要解决的主要矛盾已经变为：**用户表达的意图、程序实际执行的动作、程序报告的结果并不总是一致。** 帮助可能进入执行，EOF 可能接受默认 yes，取消可能退出整个菜单，相同版本升级仍重启，失败恢复又未必保住原始配置。仅缩短提示、增加菜单项或继续补函数级 smoke，无法收口这些问题。

下一轮先解决入口副作用、输入语义、资源归属和恢复真实性，再调整安装与维护交互。真人验收从第一次可用的安装改版开始，随后每批复测；不再等所有参数工作完成后才发现流程不适合人操作。参数迁移、NAS 原生 JSON、真实三端和 Cloudflare/ECH 验证仍在范围内。

必须保留已经有效的设计：现有模块化 Shell 架构、HAProxy/Xray/nginx 分工、五类主节点与编号、已删除的订阅/mihomo、草稿保留输入的能力、SNI 的重试/明确忽略入口、紧凑摘要，以及包含预发布的最新版核心策略。

## 5. 问题登记与证据

优先级：**P0** 会造成未经意图确认的修改、错误执行、破坏原件或虚假成功，先阻断；**P1** 影响日常安装/维护正确性或交付能力，是本轮正式验收门槛；**P2** 是低影响改进或后置研究。下面的问题尚未整项关闭；本轮完成规划导航整理，代码和实际验收仍待后续工单。已修复的旧问题另行注明。

<a id="h01"></a>
### H01 · P0：入口和只读行为存在持久副作用

`bootstrap_script_root_if_needed` 在命令派发前调用 `bootstrap_install_bundle_to_self`，仅打开菜单再退出也可能替换管理命令与安装 bundle。`bundle_root_ready` 只检查三个文件，不能证明整个运行包完整。`emit_log` 总是尝试追加操作日志，查看时的警告也可能创建日志；安装准备在参数解析前开始备份/草稿处理。

证据：历史 E01/F14 与本轮代码一致。处理：W01 定义只读边界，W08 补分发完整性；不能只给安装菜单增加一次确认而保留前面的写入。

<a id="h02"></a>
### H02 · P0：请求帮助可能进入修改动作

`dispatch_cli_command` 调用 `restart_cmd`、`repair_perms_cmd` 时不转交参数；`update_script_cmd` 没有帮助参数解析。隔离派发 `restart --help` 调用了重启处理桩；`update_script_cmd --help` 到达执行路径的 root 检查。`install --help` 也先进入锁和安装准备。

处理：W01/W03。所有命令的帮助、未知参数和缺值应先解析并结束；测试必须穿过真实派发入口，不能只测 handler 的帮助分支。

<a id="h03"></a>
### H03 · P0：EOF、取消、返回和错误没有统一语义

`prompt_yes_no` / `prompt_with_default` 忽略 `read` 失败。隔离测试从 `/dev/null` 读取、默认 yes 时得到 yes；菜单 EOF 不退出而反复处理空选择。`die` 直接 `exit 1`，外围 `run_menu_choice … || true` 不能把它变为可恢复的菜单错误。

处理：W01 先保证 EOF 不执行，W07 完成返回/编辑/取消。每次菜单动作重建上下文，防止中断后的全局变量污染下一次动作。

<a id="h04"></a>
### H04 · P0：IPv6 禁用开关吞参，输入意图不完整

`install_value_specs` 把 `--no-ipv6` 定义为取值参数。隔离结果：单独使用返回“需要值”；后接 `--disable-warp` 时返回成功，`SERVER_IP6` 变成该开关文本，而 WARP 禁用未被应用。当前还把“没提供”“明确禁用”“探测为空”混用；有探测默认时回车并不跳过，无探测值时交互又可能覆盖显式地址。

对应 E02/F04/F16。处理：W03 实现参数存在性和互斥检查，W05 让 IPv6 默认与交互一致；不能仅修改提示文字。

<a id="h05"></a>
### H05 · P1：可选高影响动作默认 yes

安装输入中网络优化、Joey 内核、WARP、nginx 主配置接管仍有 yes 默认。旧计划中的新默认值只是建议，未成为代码行为。一路回车可能改变系统网络、安装内核或注册外部设备。

对应 E03/F17。处理：W05 对新装采用明确的默认关闭与影响说明；已有安装保留原先显式选择，不借改默认值自动关闭功能。

<a id="h06"></a>
### H06 · P1：新装、重装、草稿恢复和输入顺序混在一起

必填项提前校验已改善，但 UUID/shortId/path 等自动值仍增加前置负担。直接 CLI 安装主要加载草稿，菜单进入安装前已加载面板状态，两种入口可能继承不同值。草稿省略 `SERVER_IP6`、`NET_BBR_KERNEL`、`NGINX_MAIN_MANAGED`、`ROUTE_BLOCK_CN`、`WARP_PROFILE_SOURCE` 等选择，重试不保证恢复同一意图。最小镜像的输入生成/探测又依赖尚未准备的工具。

对应 E04/F08。处理：W05 明确四种任务、草稿版本和显式恢复，先收必要输入，自动凭据只生成一次；依赖准备与预检分阶段。

<a id="h07"></a>
### H07 · P1：证书模式回车可能切换成另一种模式

`cert_mode_choice_value acme-dns-cf` 返回 `3`，而 `normalize_cert_mode 3` 返回 `existing`；菜单有两个 existing 项，ACME 实际是 `4`。本轮隔离复现 `acme-dns-cf → 3 → existing`。变更证书模式时按默认回车可能改变模式。

这比 E10 记录的数字/文字不一致更严重。处理：W03 修复枚举往返，W05 收敛为三个唯一模式；保留历史 CLI 数字别名的兼容边界，不能重新解释旧脚本的数字。

<a id="h08"></a>
### H08 · P1：无参数 SNI 检查仍可能探测错目标

普通无参数入口和 HTTP `--connect-to` 已修复，但 `sni_check_cmd` 读取已保存 SNI 后重新构造 `SNI:443`，未使用保存的 `REALITY_TARGET`。合成状态 `front.example` / `upstream.example:8443` 实际探测 `front.example:443`。现有回归中两者恰好相同，掩盖了此问题。

`--timeout 0` 仍接受，负数 `-1` 已拒绝；旧记录“0/负数都待修”应修正。DNS 查询无界、相对重定向判定、用证书签发者推测 CDN 等也需分清事实和建议。处理：W06，保留已修正的 HTTP 连接方式；对应 E07/E08/F03。

<a id="h09"></a>
### H09 · P1：地址校验不能阻止明显非法输入

`is_ipv4` 的 awk 在提前 `exit 1` 后仍执行 `END { exit 0 }`。本轮隔离测试接受 `not-an-ip`、`999.999.999.999`、`1.2.3`。`is_global_ipv6` 主要检查前缀，不能替代完整地址解析。

处理：W03 按字段验证域名/IP/端口，先保证现有支持范围正确；不顺带扩大 REALITY target 的地址语法。

<a id="h10"></a>
### H10 · P1：程序推荐的修复命令实际不接受参数

帮助/README/诊断推荐 `apply-config --manage-nginx-main` 和 `apply-net-opt --bbr-kernel none`，相应 handler 只有帮助或报错分支。本轮隔离调用均报未知参数。README 对一般 `--opt=value` 的承诺也超过当前解析覆盖。

实机报告里“修复建议可执行”的评价应降为“提示说明有价值，命令契约待修”。处理：W03/W13 对每条展示给用户的命令做派发级验证，并保留影响预览。

<a id="h11"></a>
### H11 · P0：服务重启失败仍报告成功

`restart_service_if_present` 用 `|| true` 吞掉 systemctl 失败，`restart_cmd` 最后输出“服务已重启”。本轮让三个重启桩均返回 17，得到三次失败尝试、整体返回 0、成功提示。

处理：W04 逐服务记录结果，成功必须来自实际状态和有界健康检查。`repair-perms` 等维护命令也不能将“尝试过”当作“已恢复”。

<a id="h12"></a>
### H12 · P0：卸载可能覆盖未托管 nginx 原件

`restore_nginx_main_config` 不以 `NGINX_MAIN_MANAGED` 为前提；查找备份的深度为 3，而当前 `<timestamp>/etc/nginx/nginx.conf` 布局深度为 4。合成文件树中，无论 managed=no 或 yes，存在的原件备份均被漏掉，当前自定义主配置被默认文本覆盖。卸载无条件调用该恢复函数。

遗留清理还会停止 `warp-svc`、删除较广路径；共享 `/root/.acme.sh`、WARP 与 purge 包列表的独占归属没有被完整证明。处理：W02 建立资源归属和独立的首次接管原件；没有证据时保留资源并明确报告，不能推测默认配置等于原配置。

<a id="h13"></a>
### H13 · P0：备份未必保留操作前状态

`backup_path` 重复复制会覆盖第一次快照。隔离测试先保存 BEFORE、修改为 AFTER、再次备份，最终备份成为 AFTER。备份 ID 仅精确到秒，清理发生在动作前期；帮助、取消或无变更流程也可能消耗保留名额。缺少“原本存在/不存在、归属”清单，恢复时不能可靠区分应还原、应删除和应保留。

处理：W02/W04。单次操作首次快照不可变，操作 ID 唯一，首次 nginx 接管原件独立于轮转的事务备份；无操作不创建或淘汰备份。

<a id="h14"></a>
### H14 · P1：配置、运行状态、state 与导出可能不同代

`finalize_installation` / `apply_managed_files` 在服务变更之后写 state/output 失败时直接返回；`change_uuid_cmd` 未统一纳入恢复。核心二进制替换后，资源安装或 setcap 失败也可能留下部分新内容。恢复函数吞掉部分错误，不能证明旧服务已恢复。

对应 F09/F10。处理：W04/W08 用同一操作清单和前代快照覆盖配置、核心/资源、状态、链接、PNG，验证恢复后的实际服务。此为已核对的失败窗口，尚不是本轮真实断电或磁盘故障测试结果。

<a id="h15"></a>
### H15 · P1：同版本升级和跨菜单版本上下文不符意图

同版本升级仍下载、替换和重启，已在 E12/F15 实机记录。另有本轮隔离复现：菜单内保留 selected=`v26.9.9` 后发起 requested=`v26.10.1`，下载桩仍收到旧 selected。`install_xray` 只判断已有上下文是否 ready，没有保证它属于本次动作。

处理：W08。版本只在一次动作内锁定，下一次动作重新解析；可信身份相同即无操作，真正重装用显式意图。

<a id="h16"></a>
### H16 · P0（候选拒绝）/ P1（身份）：校验可被调用上下文绕过

`xray_validate_candidate_commands` 的部分 grep/条件断言依赖 `set -e`，放在 `if` / `||` 调用链时不再阻断。隔离假核心输出合法 version、无效 x25519/vlessenc 内容，配置测试桩返回 0，受保护调用最终仍接受候选。现有小配置只是 dokodemo/freedom、socks/freedom，不是实际五类节点配置。

解析得到的 tag/commit/摘要没有形成完整持久安装清单；bootstrap 脚本 ref、下载 bundle 与旧安装回退也缺乏一致身份。固定 `/tmp` 候选 JSON 名称不属于独立操作目录。处理：W08，候选拒绝守卫提前进入第一批 P0；不重写已完成的 latest 解析器。

<a id="h17"></a>
### H17 · P1：节点名字与实际传输语义不一致

`build_xhttp_split_h3_extra_json` 把 ALPN 放在 `downloadSettings` 根部，官方要求在 `downloadSettings.tlsSettings.alpn`。IPv6 split 的外层 URI 使用 VPS IPv6，绕过名字承诺的 CDN 上行；内层 JSON 地址也使用方括号形式，需与 URI authority 表示区分。H3 的 xpadding 还未覆盖需要的各层。

对应 F05/F06。处理：W09/W11，从同一节点定义生成 URI/PNG/原生 JSON；按上行、下行、TLS/REALITY 层逐项验收，不能只证明能联网。

<a id="h18"></a>
### H18 · P1：功能配置不能等同于能力已验证

H3 判断主要依赖 nginx 模块和证书模式；`existing` 可能是公网证书、Origin CA 或自签，模式不能证明普通客户端信任。H3 缺少明确启用意图与完整端口冲突预检。当前证书对解析也不等于 SAN、有效期、完整链和信任正确。

对应 F07、E09/E15。处理：W06/W09/W12，分别展示已配置、组件支持、归属正确的监听、外部可达、客户端已验证；保留已经修复的非 nginx UDP 归属检查。

<a id="h19"></a>
### H19 · P1：获取节点和恢复导出仍绕路

`show-links --qr` 在完整部署报告后才显示二维码，长 split 码在终端不易扫描，缺少按节点选择。缺 PNG 时建议执行 `apply-config`，使恢复派生文件牵连服务变更。`show-links` 本身只读取已有文件是正确行为，应保留。缺 qrencode 或备份失败时可能保留旧 PNG，变更凭据后需防止用户继续取得旧码；链接 Markdown 的 0644 与私有 QR 权限也不一致。

NAS 原生 JSON / `export-client` 尚未实现。对应 E11/F18。处理：W11；摘要、完整资料、单节点二维码、显式导出各有明确用途，派生文件修复不重启服务。

<a id="h20"></a>
### H20 · P1：参数契约尚未成为可验证的实现

当前生成/回读仍主要使用 clients，导出保留旧的显式 xmux 值；`XHTTP_ECH_FORCE_QUERY` 可设置、保存和显示，但没有有效生成效果，官方 TLSConfig 也无该字段。`PARAMETERS.md` 中的 users、xmux、ECH 变体和 NAS 合同仍是待实施设计。

别名迁移本身不等于当前节点必然失效。处理：W10，按准确核心版本迁移并保留旧凭据和用户意图；不能借“最新参数”整批覆盖已有定制。对应 F13。

<a id="h21"></a>
### H21 · P1：面板缺少任务层次与可信完成反馈

未安装和已安装状态仍共享平铺的 19 项动作。变更前缺少“哪些链接须重导入”和“哪些连接会中断”的区别。面板 TCP 标注不清；深诊断为显示与结论重复做配置/TLS 检测，本地 TLS 探测无超时，用户可能长时间看不到进度。

对应 E13/F11/F19。处理：W06/W07，让日常入口保持廉价读取，深诊断按一次采集复用结果，动作完成说明实际状态和下一步。

<a id="h22"></a>
### H22 · P1：当前文档入口与实际推进脱节

旧 `PLAN.md` 仍把 T01 列为下一项，保留旧 SHA 与 CI 失败；详细旧计划前半与附录状态混杂。README 对受控灰云连接地址和第三方 REALITY SNI 的解释有混淆，修复建议、默认值和参数语法也存在漂移。

处理：本轮归档旧入口、建立当前入口与工单映射；W13 随实现更新产品帮助/README。历史报告不改写成成功，旧技术设计仍可引用。

<a id="h23"></a>
### H23 · P1：现有测试没有覆盖真人失败方式

125 条 smoke 多为函数或桩验证，缺少真实 PTY 的 EOF、返回、取消、默认值和跨菜单动作。安装容器预装工具、跳过 SNI、关闭 WARP/网络优化/主配置接管、使用自签，无法代表极简 VPS 默认安装。PNG 头与数量不能证明真实解码、扫码导入及编辑后字段保留。

最终公开入口安装为非交互；三端 GUI/原生传输、真实 Cloudflare/ECH/H3 和持续运行未验收。处理：W13 从首个工单补行为回归，W14 前置真人操作，W15/W16 提供真实路径与生命周期证据。

<a id="h24"></a>
### H24 · P1：自动续证缺少与手工维护相同的恢复约束

生成的 ACME reload helper 顺序提升证书/私钥，缺少共享锁、SAN/完整链检查、服务健康与成对恢复。外层申请流程还依赖可能已被 helper 移动的 staging 文件，需要受控集成测试核实实际回调时序。

处理：W12。代码路径风险已经核对，不能写成“本轮实测续证失败”；自动回调与人工 renew 共用最小必要 nginx 应用和失败恢复。

## 8. 官方字段核对与保留研究

本轮使用 Xray 官方知识技能，并按仓库要求回到 `docs/stable/config/` 与 `source/`；未以 `changelog/`、`extracted/` 的人工摘要替代源码。

| 字段/行为 | 核对结论 | 依据 |
| --- | --- | --- |
| TLS ALPN / ECH | ALPN 位于 TLS 设置；有 `echConfigList` / `echSockopt`，无 `echForceQuery` | [transport_security.go](../.claude/skills/xray-core-official-knowledge/source/config/transport_security.go)、[TLS 文档](../.claude/skills/xray-core-official-knowledge/docs/stable/config/transports/tls.md) |
| `allowInsecure` | 该版本设置为 true 会得到已移除功能错误；不能作为 H3/证书修复办法 | 同上源码 |
| REALITY `password/publicKey` | 非空 password 优先；原生 JSON 与 URI/客户端别名分开兼容 | 同上源码 |
| VLESS `users/clients` | 两者兼容；非 nil 的 clients 覆盖 users，空数组也会触发 | [vless.go](../.claude/skills/xray-core-official-knowledge/source/config/vless.go) |
| xmux | 正的 maxConnections/maxConcurrency 互斥；整块零值有核心默认 | [transport_method.go](../.claude/skills/xray-core-official-knowledge/source/config/transport_method.go) |
| H3 选择 | split HTTP 拨号检查 TLS NextProtocol 仅为 h3 后选择 UDP；错误层级不能证明 H3 | [dialer.go](../.claude/skills/xray-core-official-knowledge/source/transport/internet/splithttp/dialer.go) |
| REALITY target / serverNames / 可选签名 | 保留实际 target、SNI 与回落语义；签名条件不升级为普通节点硬门槛 | [REALITY 文档](../.claude/skills/xray-core-official-knowledge/docs/stable/config/transports/reality.md)、[参数契约](PARAMETERS.md) |

低优先级另记：**B01** 静态页 Subscribe 表单 GET 到 `/`，未见订阅处理，后续去掉无实际作用的行动入口，不建设邮件系统；**B02** 缓存建议的 `(host == domain) OR (path contains value)` 比“指定主机且指定路径”更宽，需要区分专用域名与共享域名规则。均进入 W17；本轮没有改站点或 Cloudflare 配置。

复审后的执行顺序和每项完成定义以 [详细推进计划](PLAN-UX-RELIABILITY.md) 为准。问题关闭需要代码/行为证据；文档写出决定本身不关闭问题。

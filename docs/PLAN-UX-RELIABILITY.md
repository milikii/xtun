### W01 · 入口只读、帮助与退出约束

**目标：** 用户只查看、求助、输错或退出时，不发生持久安装；EOF 不成为同意。依据 D02/D04，覆盖 H01–H03。

**改动范围：** `xtun.sh`、`lib/cli/core.sh`、`lib/base/input.sh`、`lib/base/helpers.sh`、`lib/cli/install.sh`、`lib/install/self.sh`。

1. 在 bootstrap 持久安装、root 检查、锁、备份和日志前识别帮助/错误/只读入口。公共脚本确需运行包时只使用临时目录。
2. 所有 dispatch 分支正确传参；restart、repair-perms、update-script 也按统一契约处理帮助/未知参数。
3. 区分控制台消息与修改动作日志；查看中的警告不得创建操作日志。
4. 所有 `read` 显式处理失败。主菜单 EOF 退出；向导 EOF 放弃，不接受默认 yes，不反复进入菜单。
5. 建立动作返回/清理边界，输入错误可回到菜单。不能用 `|| true` 掩盖 `exit`、重启失败或清理失败；避免通过函数递归再次启动菜单。

**验证：** 使用真实派发与 PTY/无 TTY，遍历顶层和所有子命令帮助、未知项、缺值；以无 root 身份也能求助。对 bundle/命令路径、日志、备份、草稿及 service/package 调用作前后断言。测试新公开临时入口、已安装入口、EOF、Ctrl-C、TERM、菜单退出。

**通过标准：** 无一次因查看/帮助/EOF 写持久文件或进入执行桩；错误之后菜单仍可用。版本/状态读取不被误阻断。此项通过前，不将后续安装体验结果作为有效完整验收。

### W02 · 资源归属、首次原件与卸载

**目标：** 不覆盖外来 nginx，不停止他人服务，不把缺备份当作可删除。依据 D11，覆盖 H12/H13。

**改动范围：** `lib/install.sh`、`lib/base/runtime.sh`、`lib/cli/core.sh`、`lib/state.sh`，涉及 WARP/ACME/网络资源的归属接口。

1. 定义轻量文件清单：操作 ID、原本是否存在、归属、原件摘要/位置、创建/接管意图。沿用本地文件机制，不引入数据库。
2. 修正 nginx 原件查找，恢复必须检查托管归属和可信原件；找不到时保留当前文件并报告，禁止写兜底默认主配置。
3. 首次接管 nginx 原件与普通事务备份分开保留。单操作同一路径只取第一次快照，唯一 ID 不依赖秒级时间戳。
4. 列清 systemd、WARP、ACME、sysctl/内核、站点、配置和包的卸载边界。旧安装无元数据按保守兼容处理，已存在的共享资源保留。
5. 备份轮转与清理只在动作完成并满足恢复点保留规则后执行；未解决失败的记录保留。

**验证：** 有/无接管标记、有/无原件、当前布局深度、旧布局迁移；同秒两动作与重复备份；超过五次成功修改后首次原件仍在。容器/隔离 VPS 放置非托管 nginx、hysteria、warp-svc、其它域名 ACME 文件，卸载前后比对文件摘要和服务状态。

**通过标准：** BEFORE 快照不会变为 AFTER；未托管资源不变；卸载输出列出删除、恢复、保留和未能确认项。无原件时能安全停止/保留，而不是制造一个“恢复成功”。

<a id="w02-r"></a>
#### W02-R · 首次不存在记录、必需备份证据与共享服务（P0）

**依赖：** W01-R。问题为 [H27/H28](REVIEW-2026-09-14.md#h27) 及 W05/W06 历史报告的共享 HAProxy 卸载遗留；依据 D11/D20。

**本次交付：** 普通备份、首次接管原件、包归属均有严格登记与失败传播；新原件摘要校验，旧 v1 摘要缺失明确提示。共享 HAProxy 的原件恢复、原先无配置、缺失、损坏、真实 reload 失败 5 个 systemd/HTTP 场景通过，详见接手报告。

**施工范围：** `lib/base/env.sh` 的 manifest/`backup_path`，归属与卸载层，和 W04 的恢复读取接口。

1. 以首次登记判断同一路径是否已备份；首次存在或不存在都只登记一次。不得因不存在的路径没有快照文件，就在后续创建后重新记录为存在。
2. manifest 初始化、追加、持久化与校验均返回真实结果；目录不可写、路径类型错误、存储不足等失败必须阻断托管目标变更。已产生但未登记的快照不能被当成有效恢复点。
3. 恢复依据只采用可核对的首次记录及原件。manifest 缺失/损坏、快照丢失或摘要不符分别报错，不能把它们解释成“原本不存在”，也不能用候选文件补成原件。
4. 共享服务的 unit/package 归属与配置归属分别记录。卸载不得删除仍被保留的 HAProxy 进程所需配置，再忽略 reload 失败；有可信原件则验证、恢复并检查实际服务，没有依据则保留必要资源并报告未完成清理。
5. 列清 xtun 创建的服务与外来共享服务的不同停止/清理规则；检查残留监听和配置结果。仅提示用户手动停止 HAProxy、或只因为 unit 被保留就报卸载成功，都不算问题闭合。

**回归矩阵：**

| 起点 / 故障 | 必须得到的结果 |
| --- | --- |
| 原本存在 → 备份 → 修改 → 再备份 | 首次原件及摘要不变，恢复原内容 |
| 原本不存在 → 备份 → 创建 → 再备份 | 首次 `existed=0` 不变，恢复删除本次创建的托管路径 |
| manifest 为目录 / 不可写 / 写入失败 | 非零退出，托管目标不变；报告无有效恢复点 |
| manifest 或原件缺失/损坏 | 不猜测、不误删；列出无法恢复项 |

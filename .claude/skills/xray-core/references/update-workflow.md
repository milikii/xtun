# 持续更新：发布、参数、设计方向与场景知识

更新的主要产物是**经过复核的知识**，不是生成器版本号或固定模板数量。
工具负责发现和保留证据，harness/维护者负责解释差异并安排验证。

## 1. 发现与刷新分开

在技能目录使用现有上游观察工具：

```bash
python3 scripts/upstream.py check --cache /private/path/upstream-cache.json --output /private/path/new-observation.json
python3 scripts/upstream.py check --offline --cache /private/path/upstream-cache.json
```

联网报告应同时包含稳定版、预发布、最新发布、Core main 和 docs 的观测。
离线沿用缓存原时间，不把网络失败说成“没有更新”。查询依赖版本时从所选 Core 的 go.mod 出发。

已有 `.github/workflows/upstream.yml` 定期/手动保存观察报告，**只负责元数据**：
它不会自动获取并理解所有 PR、更新参数摘要、改配置、创建维护服务或发布技能版本。
不同宿主是否能定期执行维护须由使用者单独设置；本技能不自动配置全局任务。

## 2. 每次变化的复核清单

| 变化类型 | 应检查并更新的知识 |
|---|---|
| 新发布/预发布 | 完整 SHA、发布渠道、release 正文、与旧基线的差异；是否引入新的外部前提 |
| 配置 builder | 新增/移除字段、别名/优先级、接受/拒绝、单位、默认注入和互斥 |
| runtime / transport | 实际生效路径、模式选择、两端兼容、错误处理、资源与重连行为 |
| 依赖变更 | Core 真正锁定的版本、握手行为变化、客户端约束 |
| 官网变更 | 概念或示例是否超前/落后于目标 release；同步正文和仅观察新 SHA 分开 |
| 维护者讨论 | 日期、上下文、是提案/建议/测试观察还是已合入；后续是否被修改 |
| CDN/ACME/客户端 | 供应商或客户端自己的版本、套餐、证书/接口/导入能力变化 |

沿运行路径复核，不只在 VLESS 目录里做 diff。例如代理公用层或 TLS 包装器的变化也可能影响 Vision。
参考已保存的 [v26.9.30 差异](v26.9.30-delta.md)，它是旧复核的入口，不是新版本适配证明。

## 3. 知识条目的状态

每个新结论记录：主题、目标版本/commit、上游 URL、原文日期/采集时间、实际证据文件与符号、
影响端和场景、迁移影响、验证层次、剩余缺口。

以下维度独立，不用一个“已支持”标签代替全部：

- **上游状态**：提案、已合入未发布、已发布、废弃、移除。
- **知识状态**：已定位原文、构建源码已复核、运行/依赖已复核、仍有冲突。
- **验证状态**：配置构建、隔离握手、外部场景分别 passed / failed / skipped / not_run。
- **工具状态**：可选脚本是否覆盖；它不决定知识状态或内核能力。

知识已更新但工具未覆盖时，harness 仍可按官方证据工作。没有真实测试时不能写“实测可用”。
用户追新而资料滞后时，优先补查与其场景有关的差异；无法完成就说明缺口，不悄悄降级。

## 4. 写入与发布流程

1. 先获取官方原文/准确源码，按 [维护方法](maintenance.md) 固定版本与哈希，不改写历史快照。
2. 更新相关参数索引、默认值、冲突记录、设计说明及 REALITY/XHTTP/证书工作流程。
   不为每次发布复制一份互相冲突的“万能参数表”。
3. 新资料不足以支撑结论时保留待核实；不要仅凭维护者建议覆盖运行代码的事实。
4. 以不含真实凭据的案例检验知识：新字段、版本冲突、对端不支持、证书续期、CDN 条件等。
5. 对涉及运行的结论安排对应版本的构建和握手，必要时再做明确授权的外部验证。
   本轮或环境不能执行时如实记录，不把 source-reviewed 升为运行通过。
6. 更新知识修订号；仅在真的获取/验证对应资料时改来源同步时间和验证时间。
   分享技能更新之前运行哈希、引用、测试与归档检查。提交/推送/发布均需相应授权。

## 5. 面向实际使用的验收问题

- harness 面对生成器不支持的新字段，会去查源码还是直接拒绝？
- 面对“最新”，是否区分发布渠道、指出本地知识与上游差距？
- 是否解释为什么选择参数，而不是只输出一份堆满选项的 JSON？
- 是否能分清 REALITY 目标探测与认证握手，以及 CDN 边缘/回源/本机上游？
- 是否知道续期成功、deploy-hook、进程加载和证书端点验证是不同步骤？
- 是否让真实凭据只经本地程序处理，而不是让模型阅读完整节点？

场景题见 [知识验收案例](../tests/knowledge_cases.yaml)。离线测试只核查案例与资料契约，
不会冒充跨 harness 的真实推理评测。新宿主的技能发现、工具权限和隐私纪律仍需实际验收。

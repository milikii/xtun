## 1. VLESS、TLS、REALITY 与 Vision

对两个固定源码归档逐文件比较，`infra/conf/vless.go`、`infra/conf/transport_security.go` 与 VLESS Encryption 实现未变化。VLESS inbound/outbound 的主要差异是日志级别调用调整，但共享运行代码发生了实际变化：**Vision 转入 direct copy 时抑制外层 CloseNotify**。

- [proxy/proxy.go](../source/versions/v26.9.30/proxy/proxy.go) 的 direct read/write 路径调用 `SuppressOuterCloseNotify`；该函数解开统计包装后调用 `SuppressCloseNotify`。
- [TLS 实现](../source/versions/v26.9.30/transport/internet/tls/tls.go)与 [REALITY 实现](../source/versions/v26.9.30/transport/internet/reality/reality.go)在标志生效后直接关闭底层连接，避免 direct copy 后发送错误的外层 TLS alert。
- 官方修复：[e5e85ca9dada](https://github.com/XTLS/Xray-core/commit/e5e85ca9dada936ae736197ad2b7a685972e8e0f)。

因此“VLESS 配置字段没变”不能推导为“所有行为没变”或“旧握手测试自动覆盖新版”。REALITY 的依赖未升级也不代表 Core 包装行为未变化。

## 2. 新增 MASQUE transport，不等于独立 MASQUE 协议

[transport_internet.go](../source/versions/v26.9.30/infra/conf/transport_internet.go)新增 `network: "masque"` / `masqueSettings`；[transport_method.go](../source/versions/v26.9.30/infra/conf/transport_method.go)中的 `MasqueConfig.Build` 与运行端共同决定可用条件。

- 配置含 `host`、`path`、`user`、`pass`、`headers`；校验 path 模板、HTTPS authority、header 名和值。`host` / `capsule-protocol` 不能经 headers 重设；user/pass 与自设 authorization 不得冲突，user 不能含冒号。
- [客户端](../source/versions/v26.9.30/transport/internet/masque/dialer.go)和[服务端](../source/versions/v26.9.30/transport/internet/masque/hub.go)都要求非空 TLS 配置。不能因为 stream builder 接受 network 枚举，就生成明文或 REALITY 的 MASQUE transport。
- 客户端 ALPN 含 h2 且不含 h3 才走 H2/TCP；否则走 H3/QUIC/UDP。H2 TLS 握手必须实际协商 h2。服务端含 h2 启用 H2；含 h3 或不含 h2 启用 H3，可同时启用两者。双端 ALPN、监听协议与防火墙条件必须配对。
- 这是 CONNECT-IP 通道，需要地址分配等运行步骤，不是任意普通 HTTP CONNECT 代理。
- 独立 MASQUE inbound/outbound 的配置入口是 [infra/conf/masque.go](../source/versions/v26.9.30/infra/conf/masque.go)，对应 [proxy/masque/client.go](../source/versions/v26.9.30/proxy/masque/client.go) 和 [server.go](../source/versions/v26.9.30/proxy/masque/server.go)。它们不是 VLESS 用户配置，也不能与 transport 的认证字段混用。
- vendored connectip 的 [LICENSE](../source/versions/v26.9.30/transport/internet/masque/connectip/LICENSE)随源码保留。

## 3. 新增 XDRIVE transport，不能套用普通监听器模型

新增 `network: "xdrive"` / `xdriveSettings`。`XDriveConfig.Build` 支持服务名 `local`、`Google Drive`、`template`；Google Drive 要求三个 secrets（ClientID、ClientSecret、RefreshToken），template 要求非空 template。这里是构建要求，不代表账号权限、模板操作或存储可达性已验证。

- [xdrive.go](../source/versions/v26.9.30/transport/internet/xdrive/xdrive.go)：Dial 写入会话公告；Serve 启动存储轮询与清理，并非根据 address/port 创建普通 TCP listener。
- [storage.go](../source/versions/v26.9.30/transport/internet/xdrive/storage.go)选择后端；[client.go](../source/versions/v26.9.30/transport/internet/xdrive/client.go)的 TLS 设置影响访问存储服务的 HTTPS 连接。**这不等于给 VLESS 会话提供端到端加密**。
- client.go 有 REALITY 分支，不代表 JSON builder 允许此组合：`StreamConfig.Build` 仍限制 REALITY 仅用于 tcp/splithttp/grpc。必须同时核对构建层与运行层。
- 配对需共同可访问的存储与一致会话语义；local 必须使用专门隔离的测试目录。启动测试可能创建/删除存储对象，不得使用真实业务目录或把云端 secrets 写入报告。
- 不可无损表达的分享 URI 回退原生双端 JSON，不拼出看似可用的通用节点链接。

## 4. Finalmask、XDNS、UDPHop、Noise

[配置构建](../source/versions/v26.9.30/infra/conf/transport_finalmask.go)与 [MemoryStreamConfig](../source/versions/v26.9.30/transport/internet/memory_settings.go)共同变化：原先分离的管理器改为统一 FinalMask 的 DialTCP/DialUDP/Listen/ListenPacket；XHTTP 等传输运行调用随之变化。

- **XDNS**：domains 从字符串列表变成对象，含 name/lenLimit/labelLimit/types/edns0；resolvers 也为对象，含 type/settings，tcp/udp 的地址在 settings.addr。lenLimit/labelLimit 为零时分别回填 255/63，extraPoll 范围 0..3。不能复用旧字符串数组。
- **UDPHop**：不再含独立 sockopt；全零 interval 回填 30，最小值要求至少 5。不要将它与其他位置同名 udpHop 字段混为一谈。
- **Noise**：新增 type `exp`，packet 必须是字符串，由 `parseNoiseExp` 解析并校验各段；不是任意代码表达式执行接口。
- [旧 Finalmask 文档](../docs/stable/config/transports/finalmask.md)保留原样。新字段和 schema 以上述固定源码为准，不能修改旧官方正文来消除不一致。

## 5. 其他范围与非结论

`transport_method.go` 中 XHTTP/SplitHTTP 字段与 XMUX 相关规则未见本区间功能变化；Finalmask 调用链变化仍意味着必须重测实际路径。HTTPUpgrade 新增部分 Sec-WebSocket-* 请求头。FakeDNS 默认 IPv6 池改为 `2001:2::/48`。提交列表还包含 TUN、WireGuard、SS2022、依赖等变化，本简报不是全协议运行审计。

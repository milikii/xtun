# 从官方证据到配置决策

这是 harness 的工作方法，不是生成器 API。查证顺序先读 [sources.yaml](../sources.yaml)，
再进入目标版本的官方资料；已有工具只能辅助，不能决定内核是否支持某能力。

## 1. 界定任务与版本

先判断用户需要解释、审查、配置设计，还是实际实施。收集会改变决策的信息：
两端 Xray 版本、客户端真实内核/导入能力、传输、安全层、直连/CDN/反代、TLS 终止位置、域名及证书责任。
无需为一个字段问题索取整套部署信息，更不要索取真实密钥。

“最新稳定”“最新预发布”“最新发布”“main”分开查询。用户明确追求前沿时评估最新发布，
说明是否预发布；不能静默选择旧稳定版。只有观察时间可证明当时状态，不能永久称最新。
未联网则给出本地覆盖及待核验项。发布选择与行为结论是两件事。

## 2. 追踪一个参数的完整路径

| 要回答的问题 | 应查证的位置 |
|---|---|
| 名称、别名、类型、作用端 | 目标 tag 的 `infra/conf`；确认优先级与冲突处理，不只看 struct |
| 哪些输入会拒绝、忽略或被改写 | 对应 `Build()`、协议配置解析和 transport 选择逻辑 |
| 不填写时真正使用什么 | Build 后的规范化/默认注入函数及运行时；区分未填、零值、空对象 |
| 运行时是否真的用到 | 协议处理器、dialer/listener、TLS/REALITY 集成与依赖实现 |
| 两端或中间层有什么约束 | 客户端与服务端调用路径；CDN/反代、证书和平台文档 |
| 此版本为什么这样设计 | 官方 release/commit/PR/discussion 原文；后续提交是否改变结论 |

避免仅搜索同名字段就作结论：字段可能仍能反序列化，却在 Build 被拒绝；别名可能仍可用；
一个新参数也可能需要新依赖或新对端才能生效。生成器的保守限制不得被写成内核硬限制。

对答案记录必要的“参数说明卡”，不要机械堆满所有字段：

- 目标 tag / 完整 commit、证据路径和符号；
- 客户端、服务端或两端；类型/枚举/单位；
- 实际默认值、触发条件、别名优先级、互斥/配对要求；
- 本场景启用或保留默认的理由；
- 源码核实、构建测试、握手测试分别到哪一层。

## 3. 本地尚未覆盖时

1. 用官方 release/tag 定位目标，获取准确源码或完整 checkout；不要在不完整快照中编译。
2. 对照上述路径做范围明确的检查，同时核对 go.mod 锁定依赖。
3. 需要引用新官网内容时记录该文档的时间/commit；滚动文档不能替代目标 tag。
4. 可以据证据指导 harness 编写原生配置；没有必要为了使用旧脚本删字段或换协议。
5. 对未实测的部分明确写“源码已核实，运行未验证”，证据不足的部分仍标待核实。
6. 将有价值的新结论按 [持续更新流程](update-workflow.md) 回收为版本化知识。

如果可选生成器拒绝输入，先判断是脚本未覆盖还是内核真正不支持。不得只改脚本白名单、
manifest 版本或摘要标签，让旧检查冒充新版本适配。任意原生配置也不要伪造本工具 bundle。

## 4. 从配置到验证

先确定数据经过的每一跳和每处身份/证书校验，再构造各端配置。节点数量、多入站、监听端口
按需求设计，不由辅助脚本的“单 inbound”限制决定。复用现有服务前查端口、权限和既有用途，
不得覆盖外来服务。只做规划时不进行安装、签发或修改防火墙。

真实凭据遵循 [私密产物](private-artifacts.md)，由本地程序生成并注入。模型只审查去秘密后的结构，
不能通过工具输出回读真实节点；程序完成密钥配对和配置测试，返回安全的错误分类。

交付需区分：

1. 参数、未知字段、别名与两端配对审查；Go JSON 可能忽略拼错字段，`run -test` 不能独立替代这一层。
2. 对应二进制身份及配置构建；未执行不得声称通过。
3. 实际协议/认证与上传下载；负对照应证明拒绝错误身份，而不只是服务已经宕机。
4. 原部署地址、CDN、DNS、证书、第三方客户端、地区网络及性能等外部事实。

任一辅助工具未覆盖该拓扑，仍可以按以上方法设计验证；不能把跳过改成通过。
保留实际版本、测试时间与不含凭据的结论。对只问原理的用户，不强制走整套部署流程。

## 5. 两节点场景的使用示例

用户需要一个 REALITY 和一个 XHTTP CDN TLS：分别进入两份场景指南，列出它们不同的目标、
证书和中间层责任。再决定同实例多入站或独立实例及端口安排，避免两项都默认独占同一监听地址。
这只是 harness 的决策入口，不是另一套固定“双节点生成器”。

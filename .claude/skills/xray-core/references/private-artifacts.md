# 私密产物：节点只落盘，不进入模型上下文

适用于真实 UUID、REALITY 私钥及客户端 password、Encryption 材料、证书私钥、DNS API Token、
客户端 JSON 与分享链接。所谓客户端“公钥”材料或链接也可能是访问凭据，不能因此公开。

## 1. 分开结构设计与凭据处理

```text
harness：确定非秘密参数、拓扑、版本及需要验证的条件
    ↓ 非秘密请求 / 占位结构
本地受控程序：生成或从私有文件读取凭据 → 注入 → 配对与验证 → 私有文件落盘
    ↓ 仅脱敏状态、产物位置、未验证项
harness：向用户说明结果，不读取文件正文
```

- 凭据由本地随机源/已核验的官方内核命令生成，不由模型编造。
- 现有凭据由用户直接提供给受限文件或秘密存储；不要要求粘贴进聊天或工具参数。
- 使用程序构建 JSON，避免把秘密嵌进 shell heredoc、命令字符串、模板 diff 或请求日志。
- 官方命令若必须接收秘密参数，由本地程序内部处理；评估子进程参数、进程列表、日志和调试器的本机暴露，
  这不能构成对同 UID/root 的隔离保证。
- 本地校验程序返回“配对失败/字段冲突/构建失败”等固定错误类别，捕获但不转发可能含秘密的内核 stdout/stderr。
  不为排错把整个配置或日志打印出来。

## 2. 文件与返回值约定

默认目录 `0700`、秘密文件 `0600`，输出位置在版本控制之外；拒绝意外覆盖和不受控符号链接。
需要服务账户读取时只授予必要权限，不为方便改为全员可读。临时配置同样私有，异常退出清理。

返回给 harness 的结果只需要：

```json
{
  "status": "completed",
  "artifact_directory": "/private/user-selected-output",
  "checks": {
    "structure": "passed",
    "native_build": "not_run",
    "handshake": "not_run",
    "external": "not_verified"
  }
}
```

这是**非秘密返回格式示意**，不代表已执行任务。不要返回 UUID、密码、URI、证书私钥、API Token、
配置片段、二维码或可逆的编码；base64 不是脱敏。错误路径和标签也不能夹带秘密。

生成之后不得再调用 Read、cat、grep、diff 或上传工具检查真实产物内容。
由程序检查字段、权限、哈希和配对，harness 只读经过白名单筛选的报告。
对外公开报告还应去除不必要的域名、IP、私人路径和环境信息。

分享链接不能无损表达时只保留 JSON，并报告原因；绝不把退化链接当作完整节点。
将文件路径告知用户不等于已经把文件传到用户设备；传输/加密导出需另行授权。

## 3. 现有辅助工具的用途与限制

`generate.py` 的 CLI 正常输出只有数量和链接省略原因，真实配置/链接写入文件。
不应在 harness 工具中直接调用 Python API 并打印其返回的配置对象。
`check_configs.py` 与 `check_handshake.py` 有私有临时配置和脱敏报告，但只覆盖其限定输入，
并不构成任意脚本、第三方工具或整个宿主的防泄漏审计结论。

新增现场脚本先用明显虚构的测试材料验证成功、失败、超时和异常路径，再处理真实凭据。
日志、崩溃转储、备份、CI artifact、shell tracing、终端录制和自动上传都应纳入检查。
不要通过把文件移到被忽略目录就声称其已经安全。

## 4. 行为约定不等于强隔离

“不进入模型上下文”可以通过上述工作方式实现；“harness 无权看到”则需要实际权限边界。
同 UID 可以读取 `0600` 文件，root 通常也能访问其他用户文件或进程。
如果 harness 能改生成程序、读取其目录、取得无限 sudo 权限或调试处理秘密的进程，隔离就不成立。

严格要求下，应在独立账户/受限执行环境或另一安全域处理秘密，仅开放受限请求接口和脱敏返回。
文件与进程不能对 harness 可见，不能把其自身可修改的提示词当作边界。
仅在产物最后一步加密，也无法防止控制生成过程的高权限 harness 读取加密前内容。

本技能规定默认工作纪律，但**不安装或声称已经实现这种操作系统隔离**。需要强隔离时先设计并验证权限，
未建立边界就明确告知限制，不承诺“harness 绝对看不到”。
